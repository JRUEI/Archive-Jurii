04 · Recommended version control

最小可用方案：Private GitHub + main + Preview branch。

為什麼要 Private： repository 含完整逐字稿、字幕來源、歷史 Demo 與維護腳本；不應因為要部署網站就連原始工作檔一起公開。 網站是否公開，和 GitHub repository 是否公開，是兩個不同設定。

分支規則

  • main：正式網站來源。
  • codex/<任務>：先取得 Vercel Preview。
  • Preview 通過後才合併到 main。

Commit 規則

  • 一個 commit 只處理一個目的。
  • 提交前跑完整 npm run verify。
  • 內容污染警告不在沒有來源時自動修正。
05 · Before first deployment

第一次上線前還有 4 個動作。

  1. 盤點並納入版本：檢查 78 個未追蹤檔案，避免盲目執行 git add .。
  2. 建立遠端：新增 Private GitHub repository，將本機分支改為 main 並 push。
  3. 連接平台：在 Vercel 匯入該 repository；專案已在 package.json 指定 Node.js 24.x。
  4. 先 Preview 再 Production：確認 8 集、404、安全標頭與手機版後，再讓正式網域指向該部署。

目前不要直接正式部署的原因

網站程式本身已經可建置；問題是現在的 Git 只有 19 個 tracked files。 若直接使用 Git-based deployment，多數頁面、內容與元件不會存在於遠端 repository。 先完成一次乾淨的版本盤點，才有可靠的回復點。
