# 集數檔製作流程

每集一個 `content/episodes/YYMMDD.md`，檔名跟 front matter 的 `date` 對得上。內文依序是 `## 【精簡總結】`、`## 【無損還原】`、`## 【完整逐字稿】`。欄位與長度限制以 `scripts/validate-content.mjs` 為準。

## 段落格式

```markdown
### [12:34] [標籤] 標題

一句白話簡述，30～80 字，不以 * - > # 開頭。首頁目錄點開這一段時顯示的就是它。

* **小標**：這一段講到的內容
```

`[12:34]` 是這一段開始的那一列逐字稿的時間碼，一律寫成整秒 `mm:ss`（逐字稿那一列寫 `[12:34.6]` 也對得上，只比整秒部分）；超過一小時分鐘繼續往上數，逐字稿的 `[1:02:00]` 寫成 `[62:00]`。逐字稿模式的段落清單點時間碼會跳到那裡。

「」裡的字要能在逐字稿裡原文找到（比對方式見〈逐字稿斷句〉）；其他敘述只寫逐字稿講到的事，不補推論。

日文自動字幕放在 `content/YYMMDD.ja.vtt`（跟集數檔同名），拿來對照中文逐字稿看不懂的地方、取斷句的時間碼（見下一節），不從裡面補內容。從直播存檔抓：`yt-dlp --skip-download --write-auto-subs --sub-langs ja --sub-format vtt`。

## 逐字稿斷句（熟肉斷法）

逐字稿一列是一口氣唸得完的短句（`[mm:ss] [講者] 文字`），做法仿 B 站漢化組的熟肉字幕，不是固定秒數一列，也不是一整句一列。

1. 句子從日文字幕還原：自動字幕裡的 `<00:00:01.234><c>字</c>` 是逐字時間，照 `。？！` 先切成一句一句，每個字的開口時間都查得到。再逐句翻成中文。
2. 一列長度：一口氣的量，字數中位數 8～12 字，最長不超過 17 字。一句講很長，就在語意停頓處切成幾列；一列只放半句到一句，不把兩個完整的句子擠在同一列。
3. 無標點：句末不加 `。！？`，同一列裡的逗號、頓號換成半形空格。語氣字（嗎、呢、啦）照留，`［笑］`、`［唱歌］` 這類標記沿用原本寫法。
4. 時間碼是這一列第一個字開口的時間，捨去到 0.1 秒（寫 `mm:ss.d`，例如 `[13:32.4]`）。列表上只顯示到整秒，小數是給字幕疊層對時間用的。相鄰兩列不能同一整秒（看 `mm:ss` 那一段）：撞秒就合併成一列，或把切點移到下一個落在不同整秒的字。
5. 日文字幕該處沒有逐字時間（整塊出現）時，用那一塊字幕的開始時間，照語意與字數切，一樣不撞秒；這類列沒有可對的字，寫整秒（`[mm:ss]`）。
6. 單列口語字數上限 60（不含 `[音效]` 標記）；同一整秒、時間倒退（含小數），驗證器都會警告。

切完、寫好整秒時間碼之後，用日文字幕把小數補上：

```powershell
node scripts/stamp-times.mjs YYMMDD
```

小數是 YouTube 自動字幕的逐字開口時間，捨去到 0.1 秒；工具怎麼挑字、對不上的列怎麼處理，寫在 `scripts/stamp-times.mjs` 開頭。這些小數是字幕時間，不一定貼著實際聲音，字幕疊層另外留了延遲旋鈕可以微調。

- 整秒的窗口裡沒有任何字的列（約 3%，多是語氣詞或音效）維持整秒，不算錯。
- 句首的列（約七成）小數跟字幕開口時間一致；句中切開的列是推估，手對過的 33 列裡約六成準到 0.1 秒、最多差 0.9 秒。
- 工具不改已經有小數的列。重切某一集時，先把時間碼寫回整秒再跑，不要留舊小數。
- 小數不會動整秒部分，所以整秒標籤本身差一秒的列，補了小數也還是差一秒（例如 0925 的 `[14:45]`）；重切時整秒標籤以日文字幕的開口時間為準。

做完看分布：字數中位數落在 8～12、5 字以下的列不超過兩成、超過 17 字的列個位數。偏離很多，就是切得太碎或併得太多。

「」引文可能被斷在相鄰幾列；比對引文時忽略標點、空白和換行，整份逐字稿裡找得到就算。檔案裡不補括號、保持原樣；跨列引述的括號由顯示端處理：字幕疊層一次只顯示一列，所以每一列各自補成對（開頭落在引述裡就補「，結尾還沒關就補」）。這個做法靠檔案裡的「」本身要對，驗證器會警告落單的」、前一個「還沒關又出現「、整集結束沒關、一段引述撐超過 8 列或 40 秒。

## 切段規則

各集段數要能互相比較，所以每集都照同一套規則切，不看當集內容多寡調整粗細。

1. 一段＝一個話題對象：一件事、一個物件、一個人、一個作品，或一則觀眾提問。同一個大主題底下換了子題，也算換話題（例如同樣聊飲料，「滴酒不沾」和「為了減肥喝咖啡」是兩段）。
2. 話題對象換了，而且新話題講滿 60 秒（看逐字稿時間碼，剛好 60 秒也算），才開新段。
3. 同一件事的延伸細節不開新段。不到 60 秒的插話（謝禮物、打招呼、訊號不好、看時間、跟狗說話）或短話題，併進前一段；連續好幾個短話題也一樣全併進前一段。
4. 觀眾提問一則一段。連續幾則各自不到 60 秒，併成一段 `[問答]`；講滿 60 秒的那則單獨一段，標籤照內容下。
5. 唱歌一首一段；介紹寫真集、照片時，照她自己講的區塊分段。
6. 謝 TOWER、謝禮物，一個人講滿 60 秒才單獨一段 `[感謝]`，不到的寫成條列併進當下那段。
7. 段落照播出順序排，不跨時間合併。隔一陣子又回到先前的話題，就在那個時間點另開一段，標籤沿用；所以相鄰兩段可以同標籤。
8. 開場和結尾各算一段，不受 60 秒限制。
9. 條列只寫這一段時間範圍內講到的內容。

### 分界落在哪一列

新段從「大半在講新話題」的那一列開始。一列前後講兩件事時，比兩邊的字數（不算標點）：差不多就歸字多的那邊，完全一樣就留在前一段。前一段的條列可以引那一列開頭講完舊話題的那句；話題怎麼接過去的，可以在新段寫一條過場條列。

## 標籤

- 節目結構固定用這幾個：`開場`、`結尾`（收播前的告知與道別）、`問答`（回答觀眾提問）、`告知`（活動、商品、節目宣傳）、`互動`（點名、猜謎、問觀眾問題這類要觀眾一起參與的）。
- 容易混的：
  - `互動` 是她問觀眾、`問答` 是觀眾問她。
  - `挑戰` 是她當場試著做做看（還跳得出來嗎、口技）；`遊戲` 是玩遊戲或聊遊戲。
  - `生日` 講生日；`活動` 講談話會、簽名會、お渡し会這類活動本身。
  - `成員` 講 ≒JOY 成員的事，包括去看成員的舞台；成員以外的人（工作人員、朋友）用 `人際`，家裡的人用 `家人`。
  - `作品` 只用在她自己參與的作品（例如〈夏はジュエリー〉），別人的歌用 `音樂`，寫真集用 `寫真集`。
  - `LINK` 講 ≒JOY LINK。
- 內容標籤先沿用既有的，同義詞不另開：

## 檢查

```powershell
npm run validate:content
```

段落缺時間碼、時間碼沒有比上一段晚、對不到逐字稿任何一列，都算錯誤，會擋部署；逐字稿的小數時間碼只准一位（`.4`，兩位以上會被當成不可解析的列）。段落不到 60 秒會出警告，照規則 3 併進前一段。逐字稿單列超過 60 字、跟上一列同一整秒、時間倒退、整集沒有小數時間碼、「」沒成對也是警告，不擋部署，照〈逐字稿斷句〉處理。
